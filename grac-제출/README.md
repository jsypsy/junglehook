## 구성 — 왜 이렇게 내는가

한줄팡이 보완요청 받은 5개 항목(게임설명서에 아이템·재화 명시, 플레이 영상, 실행 웹 URL, 용량 확인 자료)을
슈팅스타처럼 **처음부터 다 낸다.** 슈팅스타에서 두 번 보완을 겪은 원인(제명 중복·제명 표기 불일치)은
이번엔 해당 없음 — 「날아날아」는 동명 게임이 없고(D-020), 게임 화면 제목도 같은 한글 표기다.
단 **접수 직전 GRAC 등급분류 검색으로 동명 재확인**은 그대로 한다(D-002·D-020 원칙).

### 다시 찍는 방법

```
node tools/grac-shots.mjs                       # 헤드리스 크롬 + CDP, 13장 자동 (약 40초)
```

장면은 `src/main.ts`의 DEV 훅 `window.__nara` 위에 스크립트가 심는 `__shot` 도우미(`tp`·`hang`·`wall`·
`chanceCard`·`gauge`·`dash`·`die`)로 만든다. HANDOFF의 "순간이동 캡처 함정" 세 가지(anchor 풀고 옮기기,
`chanceStepM=1e9`, 저장값은 reload)가 스크립트에 반영돼 있다. 잎 배치가 시드 랜덤이라 `hang`은 잎을
찾아 로프를 직접 건다(닿는 잎이 없어 추락하던 첫 시도의 교훈). 벽 장면은 위협 속도를 0으로 두고 잎 기준
250px 뒤에 세워 잡히지 않게 한다. 수동 촬영이 필요하면 `tools/shot-receiver.mjs`(PNG 수신구)를 쓴다.

## 접수 절차 (남은 것은 전부 사용자 몫)

동결 전 할 일이었던 코드 쪽 항목은 끝났다: junglehook 합류(B36) · 효과음 제거(B39, D-022) · `?p=` 프리셋 배포본 제거(B40,
D-023) · 동결 빌드로 zip·해시·스크린샷·PDF 재생성 · gh-pages 게시 + SHA-256 대조.

1. **[사용자] GRAC 등급분류 검색으로 「날아날아」 동명 재확인** (슈팅스타 1차 보완의 원인).
2. **[사용자] 플레이 영상 촬영** → `04_게임플레이영상_날아날아.mp4` (git에는 넣지 않는다). **B40 빌드**(테스트 배포 또는 심의용 웹
   주소)로 찍는다. 시작 → 매달리기·날아가기 → 계절 변화 → 슈퍼 찬스(카드·3바퀴·게이지·대시) → 벽괴물 경고 → 사망 →
   결과 카드(이어하기 버튼)까지 한 판이면 된다.
3. **[사용자] 사업자등록증 · 게임물제작업자등록증** — 한줄팡·슈팅스타 제출본과 동일 (토니소프트). 상호가 사업자등록증·콘솔
   등록자명과 **글자 그대로** 같은지 대조 (한줄팡의 `토시소프트` 오기 사고).
4. **[사용자] GRAC 접수 + 수수료 결제** — 신청서 「게임물 개요」란에 `00_게임물개요_1000자.txt`, 첨부에 01·02·03 PDF + 04 영상 +
   `날아날아_게임빌드.zip`. 모의계산 https://www.grac.or.kr/SupplementaryService/SimulatedCaculation.aspx
5. **접수 후에는 게임 내용을 바꾸지 않는다.** UI·버그 수정은 무방(플레이북 §4). 배너 광고는 설명서 10항에 미리 적어 두었다.
   뒤로가기 확인 창·리더보드·공유를 넣게 되면 01 문서 4항·6항·13항, 03 문서 3항·6항을 고친다(내용 변경은 아니다).
6. 등급분류 결정이 나면 콘솔 앱 정보에 증명서·등급분류번호·이용등급을 넣는다. 게임 화면에 등급 마크를 그릴 필요는 없다.
