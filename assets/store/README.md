# 앱인토스 콘솔 "노출 정보" 이미지

콘솔 > 앱 정보에 올리는 이미지. **`node tools/store-shots.mjs` 한 번으로 전부 다시 만든다.**
문안은 `docs/STORE_COPY.md`.

| 파일 | 요구 규격 | 용도 |
| --- | --- | --- |
| `로고-600.png` | 600×600 | **앱 로고** (필수). 봄 하늘 배경에 매달린 캐릭터 + 제목 |
| `로고-600-다크모드.png` | 600×600 | 다크모드 로고 (선택). 짙은 숲색 배경 — 어두운 목록에서 묻히지 않게 |
| `썸네일-1932x828.png` | 1932×828 | **가로 썸네일** (필수). 제목·부제 + 게임 컷 3장(봄·슈퍼 대시·가을) |
| `세로-1-매달리기.png` … `세로-6-이어하기.png` | 636×1048 | **세로 스크린샷** 6장 (요구 최소 3장) |

세로 6장: 매달리기 · 날아가기 · 슈퍼 대시 · 벽괴물 · 겨울 · 결과 카드(이어하기).
**첫 장이 목록에서 가장 크게 보인다** — 조작이 한눈에 읽히는 매달리기를 앞에 둔다.

## 만드는 방법

```bash
node tools/store-shots.mjs           # → assets/store/ (12장 전부)
node tools/store-shots.mjs /tmp/xxx  # 딴 데로 빼서 비교만
```

`tools/grac-shots.mjs`와 같은 골격(헤드리스 크롬 + CDP + DEV 훅 `window.__nara`)이다.
GRAC 캡처의 "순간이동 함정" 셋(anchor 풀기 · `chanceStepM=1e9` · 저장값은 reload)이
그대로 적용된다 — HANDOFF "작업 도구" 절 참고.

**세로형은 목표 크기로 게임을 직접 렌더한다** (318×524 CSS × dpr 2 = 636×1048).
게임은 높이(`viewH=749`) 기준으로 배율을 잡고 가로는 월드를 더 보여주는 구조라
어떤 크기로 띄워도 그 크기 그대로 그린다. **폰 캡처를 축소하지 않는다** — 콘솔은
해상도가 1px만 달라도 업로드를 거부하고, 축소하면 외곽선이 뭉갠다.

썸네일·로고는 게임이 세로 전용이라 `tools/store-compose.html` 캔버스로 **합성**한다.
합성용 컷은 340×630(170×315 CSS × dpr 2)으로 따로 찍어 썸네일 안에 **1:1로 얹는다**.
합성 페이지는 게임 코드를 import하지 않고 `renderer.ts`의 색·모양을 손으로 옮긴 것이다
(`Renderer`는 `Game` 상태 전체를 요구해 정지 컷에는 무겁다) — **팔레트를 바꾸면 이쪽도 고친다.**

### 겪은 것

- **헤드리스는 대기 중 프레임을 새로 올리지 않는다.** 장면을 만들고 기다린 뒤 한 번에
  찍으면 장면 초반의 낡은 프레임이 나온다 (결과 카드가 다 안 올라온 채로 찍혔다).
  → 한 번 찍어 프레임을 밀고 150ms 뒤 다시 찍는다
- **대시는 초당 50m를 간다.** `dash(m)` 뒤 기다린 시간만큼 앞으로 가 계절이 넘어간다 —
  여름 하늘에서 잡으려고 `dash(255)` + 900ms로 맞췄다
- 합성 페이지가 컷 PNG를 `file://`로 읽으므로 크롬에 `--allow-file-access-from-files`가 필요하다
