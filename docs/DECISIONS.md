역순 아님 — 번호순. 각 결정은 번복 시 여기에 취소선 대신 후속 D-번호로 잇는다.

## D-001. 장르: 원버튼 그래플 스윙, 설계 1순위: 리워드 광고 수익 (2026-08-30)

세 번째 앱의 축을 "게임(원버튼 하이스코어) + 수익(리워드 광고)"으로 확정.
후보 비교(막대 다리·탑 쌓기·궤도 전환·그래플 스윙·줄넘기·외줄 균형·동굴 활공·
회전 바늘) 끝에 **그래플 스윙** 선택. 근거:

- 홀드 → 떼는 타이밍이 전적으로 플레이어 판단 → 죽음이 100% 납득 → 이어하기 전환율
- Stick Hero처럼 원조 한 작품이 소유한 메커니즘이 아니라 장르가 퍼블릭한 영역
- 관성 스윙은 점수와 별개로 손맛이 존재 → 리텐션 보험
- 그릴 것이 앵커·로프·캐릭터·배경뿐 → 스프라이트 부담 최소 (슈팅스타의
  플레이스홀더 아트 반복을 피한다)

**수익에서 역산한 설계 원칙 5** — 규칙을 바꿀 때 이 5개를 깨는지 먼저 본다:
1. 점수는 누적형(거리) — 한 번에 잃어야 아깝다
2. 즉사 — 목숨 분할은 아까움을 희석한다
3. 죽음이 내 실수로 납득돼야 한다 — 억울하면 광고가 아니라 이탈
4. 세션 30~60초 — 너무 짧으면 잃을 게 없고, 길면 세션 수가 준다
5. 이어하기 판당 1~2회 제한 — 점수 인플레·어뷰징(abuseLevel) 방지

## D-005. 조작 규약과 물리 구성 (2026-08-30, 프로토타입 계측으로 확정)

- **선입력 버퍼링**: 홀드 중 로프가 없으면 매 프레임 타깃을 잡으려 시도 —
  reach 밖에서 미리 눌러도 닿는 순간 잡힌다 (억울한 죽음 방지, 원칙 3)
- **타깃 하이라이트**: "지금 누르면 잡힐 앵커"를 매 프레임 노란 링으로 표시
- **로프 감기(reel-in) 110px/s**: 순수 진자만으로는 고도 회복이 불가능해
  매 사이클 가라앉다 죽는다는 것을 봇 계측으로 확인 → 홀드 중 로프가 감기며
  각운동량 보존으로 속도·고도를 회복한다. 스킬 축(오래 감기 vs 빨리 전진)도 겸함
- **공기 저항 0.12/s**: reel-in이 계속 넣는 에너지의 배출구. 없으면 속도가
  무한히 붙는다(계측: 700px/s 돌파 후 계속 상승) → 드래그로 속도 상한 형성
- **reach 270→340**: 낮은 비행에서 앵커선(y≈175)까지 수직 거리가 300을 넘어
  "잡을 로프가 아예 없는" 구간이 생기는 것을 계측으로 확인
- 검증: 고도 적응형 봇이 30초 생존·314m, 속도 350~720px/s에서 안정
  (`src/core/sim-observe.test.ts` — 평소 skip, 튜닝 시 재사용)

## D-006. 물리: 무감쇠 진자 + 스윙 펌프 — "오래 돌수록 세진다" (2026-08-30, 실플레이 피드백)

- **문제**: 첫 실플레이(156m·206m)에서 "로프에 수직으로 매달린 채 좌우 운동을 잃어
  다음 앵커로 갈 방법이 없는" 상태 발생. 계측으로 원인 확인: 구속 투영이 매 스텝
  적분기 오차(-½g²dt², g=2000이라 초당 16,700)를 상쇄 못 하게 끊어 **진자가 수 초
  만에 멈춤**(60°→2°/15s). 탈출로(놓고 0.3초 안에 다시 누르면 다음 앵커가 잡힘)는
  있었지만 매달린 동안 타깃 링이 안 보여 알 수 없었다
- **결정 1 — 에너지 보존 투영**: 스텝 시작 에너지 기준으로 투영 후 속력을
  v0²+2gΔy에 맞춘다. 30초 뒤에도 진폭 유지(60°→58.7°). 90° 위로는 로프가 느슨해졌다
  스냅하며 에너지가 빠져 자연히 수평에서 캡
- **결정 2 — 감기(reel-in) 분리**: 윈치가 외부에서 일을 넣는 연산이라 투영과 분리
  (`reelIn`). 정확한 에너지 보존을 감기에도 적용하면 상승분만큼 속력을 빼앗아 모든
  봇이 5m에서 매달린다(계측). `reelGain` 0 = 속력 유지, 1 = 각운동량 보존. 0으로 시작
- **결정 3 — 스윙 펌프**: 사용자 제안("한 앵커에 매달려 붕붕 돌수록 점프력이 세지게").
  매달린 동안 진행 방향으로 350px/s² 가속, 상한 1100px/s(한 바퀴 회전 최저 속도
  √(5·g·minRope)≈950 위). 홀드 2~3초면 회전, 놓으면 ~1100으로 발사. 상한 없으면
  47,000px/s까지 폭주(계측). 스킬 축: "얼마나 돌리고 언제 놓나"
- **난이도 곡선 rampX 9000→18000**: 180m(≈15초)에 최대 난이도라 세션이 목표
  (30~60초)의 절반. 봇 계측 생존 중앙 21s→33s
- 봇 검증: angle30 봇 20시드 60초 전원 생존·746m — **너무 쉬워졌을 가능성** 있음.
  실플레이 후 gapMax·jitterMax로 조정
- 수익 역산(D-001) 점검: 죽음은 여전히 "놓는 타이밍 = 내 탓". 세션은 길어지는 쪽
- **수정(같은 날, BUILD 4)**: 실플레이 피드백 "360° 회전이 원작 스펙인가 / 너무 빨라 앵커가
  안 보인다". 장르 참조작(Stickman Hook 류)은 진자 스윙이 수평 근처까지이고 회전은 없다.
  → swingPump 350→150, swingMaxSpeed 1100→650(90° 진폭 속도 √(2g·minRope) 아래),
  minRope 90→130. 무한 홀드 최대각 83°·회전 0·각속도 2.46→0.61회전/s. 봇 거리는 유지
- **BUILD 5 "충전기"(같은 날)**: 사용자 판단 "360°는 물리 자유도의 매력이 있는데 속도 때문에
  정신없다" → 회전을 **의도적으로 충전하는 필살기**로 재배치. (1) 홀드 중 로프를 강체(막대)로
  (`rigidRope`) — 느슨한 로프로는 90° 위 스냅 손실 때문에 pump≥1000이어야만 회전이 나
  "기본 상태 아니면 불가능"의 양극단만 있었다. 강체면 pump 200으로 4초 홀드에 첫 회전.
  (2) 투영 배율 [0.5, 2] 클램프 — 정지점에서 잔여 속도를 부풀려 96°에 붙어 기어오르는
  인공물 제거. (3) cap 1050(강체 회전 문턱 √(4gL)≈1020 바로 위)·airDrag 0.2(발사 직후 감속).
  (4) 카메라 속도 줌아웃 600→1200px/s에서 1.0→0.78. (5) `?p=b4` 프리셋으로 B4와 A/B.
  회전 중 각속도 1.8회전/s는 L=130의 물리적 하한(√(4g/L)/2π≈1.6) — 더 느긋하려면 minRope↑

## D-007. 데드라인은 UI가 아니라 지형으로 — 강물 + 사거리 밖 앵커 흐림 (2026-08-30)

- 문제: 사망선(killY 830)이 화면(749) 밖이라 플레이어가 본 적 없는 선에 죽고, 로프 사거리
  (340) 밖 앵커는 "보이는데 왜 안 잡히지"가 된다. 사용자: "데드라인을 알아야 하는데 디자인이
  지저분해질까 걱정"
- 결정: HUD 요소를 추가하지 않는다. (1) **어두운 강물**을 killY 수면으로 그리고 killY를 760으로
  올려 기본 줌에서 화면 아래 끝에 걸리게 — "물에 빠져 죽었다"는 설명 없이 읽힌다. (2) 지금 로프가
  닿는 앵커만 밝게, 사거리 밖은 흐리게 — 기존 타깃 링과 같은 문법. 사거리 원·경고 텍스트·
  깜빡임은 넣지 않는다(죽음이 "내 탓"이어야 한다, D-001)
- reach 340은 유지. 실플레이에서 여전히 억울하면 그때 reach↑
- **수정(같은 날, BUILD 7)**: 강물 띠는 카메라 줌아웃 때 위아래로 움직여 "디자인 버그"로 보였다
  (사용자) → **제거**. killY 770(화면 아래로 공이 완전히 사라지는 지점). 데드라인은 대신
  **사망 연출**이 보여준다: 추락 지점 충격파·주황 파편(26개)·0.35초 흔들림·따뜻한 색 플래시 →
  "추락!" 팝 → 점수 카운트업 → 신기록 배지 → 재시작 힌트(재시작 잠금 1.0s). 피·붉은색·신체
  표현 없음 — GRAC 전체이용가 기준 유지. reach 340→450, targetBehindLimit 60→120으로
  "하단 30%에서 로프를 못 쏜다" 완화. 사거리 밖 앵커 흐림은 유지하되 대비 완화(α 0.55).
  시작 화면에 한줄팡식 3.2초 루프 데모(누르면 매달림 → 떼면 비행) 추가

## D-008. 비주얼 방향: 밝은 카툰 정글 (2026-08-30, 클로드 디자인 캔버스로 확정)

  있는 주황 공, 앵커는 덩굴 끝 나뭇가지 매듭, 타깃은 노란 링. 웹폰트 없이 system-ui 굵게(번들 0)

  없이 도형·그라데이션으로 재현(런타임 의존성 금지 원칙)
