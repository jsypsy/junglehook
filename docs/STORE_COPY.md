# 앱인토스 콘솔 앱 정보 — 입력 문안

콘솔 > 앱 정보에 그대로 들어가는 문안. 이미지는 `assets/store/` (규격·제작 방법은 그쪽 README).
등록은 콘솔 MCP `miniapp_update_basic_info` 한 번으로 전체 페이로드를 보낸다 —
**부분 갱신이 안 되므로 이 문서가 곧 페이로드의 원본이다.** 보낼 JSON은 `docs/store-payload.json`
(업로드된 이미지 주소까지 박혀 있다). ⚠️ **MCP 경로는 등급 전에는 못 쓴다** — 아래 "등록 상태" 절.
2026-09-04 현재 1·2단계는 **콘솔 웹에서 이미 임시저장돼 있다.**

> ⚠️ **게임 화면에 실제로 찍히는 문자열과 다른 이름을 쓰지 않는다.**
> 화면 문구가 기준이다: `탭해서 시작` · `꾹 누르면 매달리고` · `떼면 날아가요` ·
> `다시 누르면 다음 잎으로!` · `슈퍼 찬스!` · `꾹 누르면 도전!` · `SUPER!` · `끝` ·
> `광고 보고 이어하기` · `다시 하기` · `이번 기록` · `최고`.
> GRAC 제출 문서(`grac-제출/`)도 같은 표기다 — 갈리면 그 자체가 지적 사유가 된다.

## 상세 설명 (필수, 500자 이내)

446자. 입력란 안내가 "무엇을 보고, 어떤 버튼을 누르고, 무엇을 경험하는지"라
**실제 화면 문구를 그대로** 넣었다.

```
「날아날아」는 화면을 누르고 떼는 것만으로 진행하는 원버튼 스윙 게임입니다.

시작 화면에서 [탭해서 시작]을 누르면 바로 시작합니다. 화면 아무 곳이나 꾹 누르면 주인공이 로프를 던져 가장 가까운 잎에 매달려 그네처럼 흔들리고, 손을 떼면 관성으로 날아갑니다. 다시 누르면 다음 잎을 잡습니다. 조준도 발사 버튼도 없습니다.

앞으로 나아간 거리가 점수이고 「일수」로 표시됩니다. 250m마다 봄, 여름, 가을, 겨울로 배경이 바뀝니다. 1년에 한 번 「슈퍼 찬스」가 열리는데, 꾹 누른 채 세 바퀴 돌고 게이지의 노란 구간에서 손을 떼면 200m를 단숨에 날아가는 슈퍼 대시가 터집니다.

뒤에서는 벽괴물이 천천히 쫓아옵니다. 잎을 놓쳐 떨어지거나 따라잡히면 게임이 끝나고, [광고 보고 이어하기]로 그 자리에서 이어 가거나 [다시 하기]로 새로 시작합니다. 내 최고 기록을 넘는 것이 목표입니다.
```

## 카테고리

**게임 > 액션** (`categoryIds: [3836]`). 게임 그룹에는 서브카테고리가 없어
`subCategoryIds`는 보내지 않는다. GRAC 신청서의 장르는 "아케이드(원버튼 스윙 액션)"인데
콘솔에 아케이드 칸이 없어 액션으로 간다 — 한줄팡=퍼즐, 슈팅스타=액션과 같은 결.

## 앱 검색 키워드 (필수, 최대 10개 · 한글/영문/숫자/공백만)

```
날아날아, 스윙게임, 원버튼게임, 한손게임, 로프게임, 정글게임, 미니게임, 캐주얼게임, 아케이드, 하이스코어
```

- 앞쪽 3~4개가 가장 중요하다 (앱 이름 + 조작 + 장르).
- **상표는 넣지 않는다** — 타잔 등 타사·타작품 이름 금지.
- 특수문자가 들어가면 등록이 거부된다. 쉼표는 구분용이고 실제로는 배열로 보낸다.

## 등록 상태 — 1·2단계 저장 완료, 3단계만 GRAC 대기 (2026-09-04)

**콘솔 웹에서 1단계(기본 정보)·2단계(카테고리 및 노출)를 채우고 [임시저장]으로 넣어 뒀다.**
앱 정보 화면에 부제·카테고리·키워드 10개·로고·썸네일·고객문의 이메일이 모두 찍혀 있다.
남은 것은 3단계(게임 등급분류)뿐이고, 거기서 [검토 요청하기]를 누르면 등록이 끝난다.

### ⛔ MCP로는 이 상태를 만들 수 없다

`miniapp_update_basic_info`는 **전체 페이로드 + 검토 요청이 한 몸**이라 등급 칸이 비면
**저장 없이 통째로 거부**된다. 두 번 확인했다:

| 보낸 것 | 응답 |
| --- | --- |
| `gameInfo`에 `gameRating` 없이 | `스토어 링크 또는 게임물 등급분류증명서를 등록해주세요.` |
| `gameInfo` 자체를 빼고 | `게임 정보가 존재하지 않아요.` |

호출 뒤 `miniapp_get`은 여전히 전부 빈 값이었다. **게임 카테고리 → `gameInfo` 필수 →
증명서 필수**로 물려 있어 MCP에는 빠져나갈 구멍이 없다.

**콘솔 웹에는 [임시저장]이 있다.** 단계마다 검토 요청 없이 저장되고, 등급 칸이 비어도 받는다.
MCP 문서에는 이 버튼에 해당하는 tool이 없다 — **등급 전에 앱정보를 넣어 두려면 콘솔 웹이 유일한 길이다.**

**형제 앱 문서의 기술이 틀렸다.** 한줄팡·슈팅스타 기록은 "등급 정보가 비면 앱정보 **검토가
반려된다**"고 적었는데, MCP로는 검토에 들어가지도 못한다. `storeLink`는 다른 앱스토어에
이미 출시된 게임의 자체등급분류용이라 여기 해당 없다.

### 3단계에서 요구하는 것 (전부 GRAC 결정 뒤)

등급분류번호 · 분류일 · 게임물제작업자 신고번호 · 이용등급 · 내용정보 · **대표자 인감 또는 사인
이미지** · **게임 주요화면 2쌍**(자체등급분류 게임물 화면 + 앱인토스 게임물 화면). 그리고
"앱을 등록하기 전에 확인해 주세요" 5개 체크 → [검토 요청하기].

> 인감·사인 이미지는 문서에 없던 요구다. 형제 앱 때도 넣었을 텐데 기록이 없으니
> 등급 수령 시점에 파일부터 찾아 둘 것.

**결정이 나면**: `docs/store-payload.json`의 `_등급_수령후_추가` 자리를 채워
(`ageRating: ALL` · `bizName: 토니소프트` · `ratingNumber` · `contentRatings: ["NONE"]`)
`miniapp_update_basic_info` 한 번이면 끝난다. 이미지 9장은 이미 `static.toss.im`에
올라가 있어 다시 만들 필요 없다.

⚠️ **증명서 PDF는 MCP로 못 올린다.** `image_upload_url`은 png·jpg만 발급한다. 형제 앱의
`gameRatingCertificateUri`(`72091/…pdf`)는 콘솔 웹에서 올려 받은 키다 — 콘솔 웹 게임
등급분류 화면에서 PDF를 먼저 올리고, 저장된 키를 `miniapp_get`으로 읽어 페이로드에 넣는다.
