# 앱인토스 출시 플레이북

_한줄팡(2026-08-21 출시)에서 실제로 겪은 절차를 순서대로 정리한 것._
_공식 가이드에 없거나, 가이드와 실제가 달랐던 것 위주로 적는다._

이 문서의 목적은 **두 번째 게임을 첫 번째보다 빠르게 내보내는 것**이다.
한줄팡에서 시간을 태운 자리(약관, 주요화면, 검수 취소)를 미리 표시해뒀다.

---

## 0. 전체 경로 한 장

```
[개발]  ait build → ait deploy → 실기기 테스트 (deploymentId 링크)
   │
   ├─[게임물관리위원회] 등급분류 신청 → 결정 (한줄팡: 접수 다음 날)
   │      ※ 게임은 등급분류가 있어야 출시할 수 있다. 제출본 = 출시본이어야 한다
   │
[콘솔] ① 앱 정보(메타) 검토 요청 → 승인
   │        ※ 승인 전에는 번들 검수 요청 자체가 불가 (MINI_APP_BEFORE_FIRST_APPROVAL)
   │        ※ 리더보드도 이 승인 전에는 LEADERBOARD_NOT_FOUND가 정상
   │
   └─② 번들 검수 요청 → 승인 (한줄팡 실측 3시간 / 4시간 반)
          → 게임 주요화면 4장 제출 → [출시하기] → 라이브
```

**앞단(등급분류)과 콘솔 검수는 병렬로 굴릴 수 있다.** 한줄팡은 등급분류 결정을
기다리는 동안 코드를 다듬었는데, 앱 정보 검토를 먼저 넣었으면 이틀은 줄었다.

## 1. 계정·워크스페이스 전제

- 워크스페이스 + 미니앱을 콘솔에서 만든다. `appName`은
  `apps-in-toss.config.ts`의 값과 **정확히 같아야** 배포가 붙는다
- **사업자 인증**이 필요하다 (한줄팡: 개인사업자, APPROVED)
- **비즈월렛**은 프로모션(광고비)용이다. 출시에는 필요 없지만 개설은 해두는 편이
  낫다 — 한줄팡에서 워크스페이스 약관 문제가 이것과 얽혀 보였다
- ⚠️ **토스 로그인 '등록하기'는 누르지 않는다.** 진행하면 쓰지도 않을 기능이
  켜지고 `USER_NAME` 수집이 고정 필수로 붙는다. 게임 식별은
  `getUserKeyForGame()`(익명 해시)로 충분하고, 그쪽이 게임 심사 요건에 맞는다.
  `TossAuth.login()`은 `authorizationCode`를 토큰으로 바꿀 **서버가 필요**한데
  정적 빌드에는 그런 것이 없다
- 콘솔 **"약관/동의문 · 서비스 이용약관 [필수]"** 화면은 전체 필수처럼 보이지만
  **토스 로그인 설정의 일부**다. 약관 없이도 앱 정보 검토는 통과한다
- 콘솔 홈의 '준비하기' 목록은 **진행 상태가 아니라 단순 바로가기 모음**이다.
  이미 끝낸 항목도 [이동]으로 남아 있다

## 2. 개발 중 — 실기기까지 도는 고리

```bash
npm run ait:build      # tsc --noEmit && vite build && ait build  → .ait 아티팩트
npm run ait:deploy     # ait deploy 래퍼 (tools/deploy.mjs)
```

`tools/deploy.mjs`가 배포 출력에서 URL을 뽑아 두 가지를 남긴다.

- `tools/latest-deployment.json` — `intoss-private://<app>?_deploymentId=…`
- `tools/deploy-qr.png` + **터미널에 QR 직접 출력** (폰 카메라로 맥 화면을 찍으면 끝)
- `npm run ait:send` — 최신 배포 URL을 **내 아이메시지로 전송**(`tools/imessage.mjs`, macOS 메시지 앱
  AppleScript). 폰 메시지에서 링크를 탭하면 토스가 열린다. 수신자는 `tools/imessage.local.json`
  `{"to": "+82…"}`(gitignore) 또는 `JGH_IMESSAGE_TO`

⚠️ **파라미터 없는 `intoss-private://<app>`은 미출시 상태에서 거부된다**
("지금은 서비스를 사용할 수 없어요"). 반드시 `_deploymentId`가 붙은 전체 URL을
쓴다. 커스텀 스킴은 주소창에 직접 못 넣으므로 `tools/go.html`을 폰 사파리에
북마크해두면 [북마크 → 버튼] 두 번으로 최신 배포가 열린다.

**화면 검수는 393×749 iframe으로 한다** (`tools/frame.html`).
iPhone 16 전체 852pt 중 **토스 헤더가 103pt를 가져간 나머지**가 749다.
OS 창을 리사이즈하지 않고도 실제 레이아웃을 볼 수 있다.

> 도트게임 주의: iframe은 맥 DPR 기준이라 **정수 배율이 실기기와 다르다.**
> 레이아웃 검수용이지 도트 선명도 검수용이 아니다.

## 3. 코드에 미리 넣어야 하는 심사 요건

한줄팡이 통과한 구성이다. **처음부터 넣어두면 심사 대응이 따로 없다.**

| 요건 | 구현 위치 |
|---|---|
| 세로 고정 + 플레이 중 화면 꺼짐 방지 | `AitAdapter.applyScreenPolicy()` |
| 뒤로가기로 곧장 나가지 않고 확인 | `onBackPressed` → 확인 모달 |
| 게임용 사용자 식별키 | `getUserKeyForGame()` |
| 리워드 광고 **사전 로딩** (노출 시점 실시간 로딩 금지) | `preloadRewardedAd()` |
| 광고 중 게임 오디오 차단 (SDK에 오디오 포커스 API가 없다) | 광고 호출 앞뒤로 직접 mute |
| 사운드 On/Off 제공 | 게임 UI |
| 백그라운드 전환 시 사운드 즉시 종료 | `visibilitychange` |
| 점수 제출은 **플레이 완료 후** (진입 직후 금지) | 게임오버 시점 |
| `eval` / `new Function` / `innerHTML` 없음 | 코드 전반 |
| 평문 `http://` · `ws://` 없음 | 코드 전반 |
| SSR 아님 (정적 빌드) | Vite |

**추가로 처음부터 넣을 것 — 한줄팡이 출시 후에야 넣은 것들**

- **이벤트 계측** (`src/analytics.ts`). 콘솔 '핵심 지표(활성·전환)'는 우리가 보낸
  이벤트를 재료로 쓴다. 플랫폼 자동 로그(진입·체류·광고재생)만으로는 "실제로
  즐겼는가"를 알 수 없다. **이벤트는 배포된 뒤에야 로그 카탈로그에 뜬다** —
  늦게 넣을수록 데이터가 늦게 쌓인다
- **kv 미러링** (`platform.kvSet`). 미니앱 주소가 바뀌면 오리진이 바뀌고
  **localStorage가 통째로 날아간다** (2026-08-25 `*.apps.tossmini.com` 전환이
  실제 사례). 최고점수·진행상태는 플랫폼 저장소에도 같이 쓴다
- **`cancelHostTopInset`** (`platform/adapter.ts`). `SafeArea.get()`은 **기기
  기준** 값이라 토스 헤더 아래에 놓인 WebView에서 상단이 이중 계산된다.
  실측(852 화면 / 749 뷰포트 / top 59 보고)으로 알아낸 보정이다. **반드시 쓴다**

## 4. 게임물 등급분류 (GRAC)

게임은 등급분류 없이 출시할 수 없다. **등급받은 게임과 출시할 게임이 동일해야
한다** — 신청 시점의 빌드를 동결해두고, 그 빌드로 출시까지 간다.

- 접수는 사용자가 직접 (게임물관리위원회 시스템). 한줄팡은 **접수 다음 날 결정**,
  보완요청 없이 신청한 대로 나왔다 (통상 안내는 10~15일)
- 제출물: 게임빌드 zip + **내용설명서**. 심의자가 접속해 플레이할 웹 주소를
  요구할 수 있어 한줄팡은 `gh-pages`에 제출본과 같은 빌드를 올려뒀다
- **제출본은 SHA-256과 함께 리포에 커밋해둔다.** 나중에 "출시본과 같은가"를
  대조할 유일한 근거다
- GRAC 구비서류 안내는 **모든 게임물 유형을 아우르는 통합 목록**이다
  (아케이드 전용 항목이 섞여 있다). 신청 화면에 없는 항목은 이 유형에 요구하지
  않는 것일 수 있으니 누락으로 단정하지 말 것
- **등급 표시는 플랫폼이 한다.** 콘솔 앱 정보에 증명서·등급분류번호·이용등급을
  넣으면 토스 앱 5.240.0+ 등급 표시 UI가 노출한다. **게임 화면에 그릴 필요 없다**
  (한줄팡은 이걸 구현하려다 되돌렸다)
- 증명서 PDF는 **AES-128 암호화**라 텍스트 추출이 막힌다. macOS
  `qlmanage -t -s 2400 -o . cert.pdf`로 이미지를 뽑아 읽는다 (**첫 장만** 나온다)

**나중에 무엇이 재신고(내용수정신고) 대상인가**

| 변경 | 내용수정신고 | 앱인토스 검수 |
|---|---|---|
| UI·레이아웃, 버그 픽스 | 불필요 | **매번 필요** |
| 리워드 광고 활성화 | 불필요 (내용설명서에 미리 기재해두면) | 필요 |
| **배너 광고 도입** | 확인 필요 — "배너 광고 없음"을 바꾸는 경우 | 필요 |
| 아이템 종류·효과, 확률 요소 변경 | 확인 필요 | 필요 |

등급 판단에 영향을 주는 것은 **아이템 구성·사행성·폭력/선정성**이다.
버튼 위치는 해당하지 않는다.
→ 내용설명서에 **"앞으로 넣을 수도 있는 것"을 미리 적어두면 재신고를 아낀다.**

## 5. 콘솔 검수 — 2단계

### ① 앱 정보(메타) 검토

앱 이름·설명·아이콘·스크린샷·게임 등급분류 정보를 넣고 검토 요청.
**이게 승인돼야 번들 검수를 넣을 수 있다.** 리더보드도 이 승인이 전제다.

> `miniapp_get`은 **검토 중인 제출본을 보여주지 않는다.** 승인 전에
> `gameInfo: null`이 나와도 실제 입력값과 다를 뿐이니 놀라지 말 것.

### ② 번들 검수

```bash
npm run ait:build && npm run ait:deploy   # 새 번들 업로드
```
→ MCP `bundle_test_push` (**`isTested: true`가 검수 요청의 선행 조건**)
→ 응답의 `privateLink`를 폰에서 열어 실기기 확인
→ MCP `bundle_submit_review`
→ 승인 후 **콘솔 웹에서 [출시하기]** (라이브 전환만은 사람이 눌러야 한다)

**소요**: 공지는 영업일 3~5일이지만 실측 **3시간 / 4시간 반**이었다.
시스템 검수 + 인력 검수 이중 구조라 심야에도 승인이 나지만, 사람 판단이 필요한
사안이 끼면 영업일 기준으로 밀린다.

**한 번에 한 버전만 검수된다** (`ANOTHER_BUNDLE_IN_REVIEW`).
화면 변경이 없는 번들로 검수 슬롯을 혼자 쓰지 말고 다음 UI 변경과 묶어 올린다.

### ⚠️ 콘솔에서 누르면 안 되는 것

- **[요청 취소]** — 취소한 배포는 `CANCELED`가 되고 **같은 번들로 영구히
  재요청 불가**다. 새 번들을 빌드해 올리는 수밖에 없다. 한줄팡에서 두 번 날렸다
- **[검토 요청]** — MCP로 이미 요청을 넣었으면 누르지 않는다. 출시 노트 모달이
  다시 뜨고 상태가 꼬인다. **MCP로 넣었으면 콘솔에서는 [출시하기]만**
- **[버전 등록]** — 새 번들 업로드 버튼이다. 올릴 빌드가 없으면 누르지 않는다

## 6. 출시 직전 관문 셋

한줄팡이 여기서 하루를 썼다. 미리 알고 가면 몇 분이다.

1. **`GAME_CONTENT_IMAGES_MISSING`** — 검수 승인 직후 나타난다. [출시하기]를
   누르면 **게임 주요화면 2종 × (자체등급분류 화면 / 앱인토스 화면) = 4장**을
   요구한다. 좌우가 **픽셀 일치일 필요는 없다** (콘솔 예시조차 서로 다르다).
   "같은 게임의 같은 화면 구성"이면 된다.
   좌열은 `dist`를 393×749 iframe에 띄워 캡처, 우열은 실기기 [테스트]에서 캡처
2. **`WORKSPACE_TERMS_AGREEMENT_REQUIRED`** — MCP로는 동의할 수 없고 콘솔에서도
   경로를 못 찾았는데, **앱 정보 승인과 함께 저절로 사라졌다.**
   앱 정보 승인 전에 이걸로 시간을 쓰지 말 것
3. **출시 노트는 필수값**이고 형식은 번호 매긴 변경사항 목록이다.
   첫 출시면 "1. 〈게임명〉 첫 출시"로 족하다.
   ⚠️ **릴리즈 노트에 심사 소명(등급분류번호·개인정보 처리 등)을 넣지 않는다**

**'출시하기'는 곧장 라이브가 아니다** — 누르면 번들 검수 요청 모달이 뜨고,
승인이 나야 진짜 출시 버튼이 산다.

## 7. 출시 후 운영

**버그가 나면** 검수를 거치지 않는 수단이 둘 있다.

- **롤백** — 콘솔 '앱 출시'에서 과거 배포 버전으로 즉시 복귀 (MCP `bundle_rollback`)
- **긴급 점검** — 앱 정보 > "긴급 점검 안내하기". 즉시 적용.
  단 **점검 중에는 출시 검토 요청이 불가**하니 수정본을 넣으려면 먼저 풀어야 한다

**리워드 광고 지면**

- 콘솔에서 지면을 만들고 `adGroupId`를 코드에 넣는다
  (이 프로젝트: `src/platform/ait.ts`의 `AD_GROUP_ID`, **아직 비어 있다**)
- 비어 있으면 광고 없이 보상만 지급하는 폴백이 돌게 짜여 있다 — 지면 발급 전에도
  게임은 정상 동작한다
- ⚠️ **실 ID로 광고를 반복 시청하지 말 것.** 인위적 노출은 어뷰징으로 걸리고
  `abuseLevel`이 붙으면 지면이나 미니앱 전체가 제한된다. 동작 확인은 한 번만
- 지면은 **23일 연속 노출이 없으면 '삭제 예정', 30일이면 삭제**된다
- 개발 중 배너는 반드시 테스트 ID(`ait-ad-test-banner-id`)를 쓴다 (실 ID 테스트는
  정책 위반)

**배너 광고 정책** — `TossAds.attachBanner`, 토스앱 5.241.0+, width 100% / height 96px.
**"배너는 상단·하단에만", "인트로·로딩·컷신·팝업 모달에 노출 금지"** 이므로
게임오버 카드에 붙이는 안은 막힌 것으로 본다.

**지표** — `dashboard_dau`·`dashboard_retention`·`core_metric_list`.
핵심 지표(활성·전환) 등록은 **콘솔 웹에서 수동**이다 (MCP에 조회 tool은 있어도
생성 tool이 없다). 게임이면 보통 활성 = 첫 게임 시작, 전환 = 게임 완료·재방문.

## 8. 콘솔 MCP

```bash
claude mcp add apps-in-toss-console --transport http \
  https://mcp.toss.im/adapters/apps-in-toss-console/mcp --client-id mcp-gateway
```

인증은 `/mcp`에서 사용자가 직접. 자주 쓰는 tool:

| tool | 용도 |
|---|---|
| `miniapp_release_status` | 출시 파이프라인 종합 판정 — **막히면 여기부터** |
| `bundle_list` / `bundle_test_push` | 번들 목록 / 테스트 푸시(+`isTested`) |
| `bundle_submit_review` / `review_list` / `review_get_feedback` | 검수 요청·상태·피드백 |
| `bundle_rollback` | 과거 버전 복귀 |
| `iaa_placement_group_list` | 광고 지면 |
| `dashboard_dau` / `dashboard_retention` / `core_metric_list` / `event_log_list` | 출시 후 지표 |

**MCP로 할 수 없는 것**: 라이브 전환([출시하기]), 워크스페이스 약관 동의,
핵심 지표 생성, 게임 주요화면 업로드. 전부 콘솔 웹에서 사람이 한다.

## 9. 환경 제약 (반복해서 부딪힌 것)

- **크롬 자동화 도구는 `apps-in-toss.toss.im`에 접근하지 못한다**
  (금융 도메인 차단). 콘솔 화면 확인은 **사용자가 캡처해서 넘겨주는 방식**이 유일
- **배포(`ait:deploy`)와 크롬 렌더 검수는 로컬에서만 된다.** 클라우드 세션에는
  콘솔 인증도 브라우저도 없다. 클라우드는 문서·코드·시뮬레이션용
- **로컬 CLI 세션은 클라우드로 옮길 수 없다** (이관은 클라우드→로컬 단방향)
- 캔버스 드래그를 크롬 도구로 흉내 낼 때, 한줄팡에서는 **드롭 지점이 블록
  중심보다 약 110px 아래**여야 했다 (손가락 위 오프셋)
